# S3 备份与灾难恢复

S3 是备份目标，浏览器通过服务端同步。正式目录统一使用 `mynote/`，不以迁移日期命名：

```text
mynote/
├── blobs/<sha256>                 # 按内容哈希复用的文件对象
├── snapshots/<timestamp-id>.json  # gzip 压缩的完整快照清单
└── latest.json                    # 最近成功快照的小型指针
```

日期只出现在快照 ID 中，不改变正式目录。已有数据切换前缀时，必须先复制并校验 blobs、snapshots 和 latest，再切换配置；不能仅改前缀并假设旧对象会自动复用。保留旧迁移目录作回滚，不再用于日常备份。

## 配置

也可通过网页左下角设置配置并测试 S3；首次保存后以 data/settings.json 为准，实时生效。下列环境变量用于尚未保存网页设置的实例。详见 [设置说明](settings.md)。

```dotenv
S3_BACKUP_ENABLED=true
S3_BACKUP_SCHEDULE_ENABLED=false
S3_BACKUP_DEBOUNCE_SECONDS=60
S3_BACKUP_MAX_WAIT_SECONDS=600
S3_BACKUP_ENDPOINT=https://s3.cn-east-1.qiniucs.com
S3_BACKUP_REGION=us-east-1
S3_BACKUP_BUCKET=your-notes-bucket
S3_BACKUP_ACCESS_KEY_ID=...
S3_BACKUP_SECRET_ACCESS_KEY=...
S3_BACKUP_PREFIX=mynote
S3_BACKUP_INTERVAL_HOURS=24
S3_BACKUP_VERIFY_INTERVAL_HOURS=168
S3_BACKUP_SERVER_SIDE_ENCRYPTION=AES256
```

`S3_BACKUP_ENABLED` 是备份能力开关；`S3_BACKUP_SCHEDULE_ENABLED` 是单独的定时开关，默认关闭。仅配置 S3 不会自动创建定时任务。应用 `.env` 修改需重新创建容器；生产更新时前后端配套切换。

密钥不提交 Git。日常备份需要目标前缀的列举、读取、写入和删除权限。`S3_BACKUP_RETENTION` 控制普通快照保留数量；已有受保护快照、恢复前快照额外保留。清理只作用于当前前缀，不处理旧迁移目录。此机制限定单服务端拥有该前缀，不能让多个服务端同时写同一前缀。

## 变更触发自动备份

两个开关都开启后，由服务端统一合并所有浏览器的改动：最后一次变更后 60 秒触发，期间新变更延后计时；连续修改最多等待 600 秒，当前已有任务时等待它结束再执行。正文增删改、历史恢复、移动及附件上传均写入持久变更记录。空同步请求、读取和校验失败不会延后计时；附件写入前先留标记，写入失败可能触发一次无变化检查，以免崩溃遗漏附件变更。

备份只确认建立本地一致快照时捕获的变更序号。上传期间产生的新序号不会被清除，会继续合并并触发下一批。手动备份成功同样确认已覆盖的改动。重启沿用持久记录和原截止时间；关闭网页不影响执行。除此之外，每 24 小时有一次兜底检查，仍按无变化跳过规则处理；每 7 天的全量核对也在备份中执行。

普通备份失败按 60 秒起步指数退避，最多 1 小时，新编辑不会绕过退避。异常大幅减少、清单损坏和恢复保护等安全错误暂停自动重试，需检查后手动成功备份解除。恢复任务/持久恢复保护期间不发起自动备份。页面显示待备份变更、预计触发时间和暂停原因。

这里合并的是一次备份任务；S3 仍按内容对象上传增量，最后统一发布一份快照，而不是每次键盘输入都请求 S3。触发从改动成功到达服务端开始计算，离线浏览器尚未上传的内容不在此次备份中。

## 备份行为与范围

当前备份范围是 `data/notes/` 与 `data/attachments/`。在写队列内为正式文件创建本地硬链接快照，随即释放写队列；随后扫描文件元数据，仅对新增、变化的文件计算 SHA-256，复用已确认上传的对象，只上传增量，最后发布压缩快照与 latest 指针。正文及同名附件均通过临时文件原子替换，因此后续编辑、替换附件、删除原文件不会改变已固定的快照。硬链接不复制全库内容，但备份期间被替换或删除的旧文件仍占磁盘，直到暂存区清理。文件数量/容量骤降会被拦截。仍会遍历文件目录、建立硬链接并读取元数据，但日常不再全量读取文件内容或列举全部远端 blobs。

**当前尚不包含 `metadata.sqlite` 中的笔记历史版本。** 完整冷备需要在停服或一致性快照下保存整个 data 目录，数据库不可仅当作可丢弃的检索索引。

Web 右侧可发起持久后台备份/恢复任务。关网页不取消任务；失败会保留状态，可重试。备份仅在本地硬链接快照建立期间排队等待写入，扫描、上传和清理期间允许正常保存。快照开始之后的修改归入下一次备份。恢复仍暂停服务器写入，浏览器编辑先保存在本机，恢复结束后按数据世代规则同步。

## 增量缓存与周期核对

`data/backup-cache.sqlite` 保存文件路径、设备号/inode、创建时间、大小、纳秒级修改时间和 SHA-256，以及按 endpoint/bucket/prefix 隔离的已上传对象记录。修改采用原子替换，同大小、同修改时间的新文件也因 inode/创建时间变化而重新计算。删除和移动由路径集合比较识别。记录仅用于加速；不属于恢复所需的业务数据。停止服务后移除此缓存会触发重新建立，不能在服务运行时删除数据库。

对象 PUT 成功后才持久确认，失败或重启后复用成功项。删除远端对象前先使缓存失效，部分删除失败会强制下次重新列举。首次运行、目标切换及全量核对到期会重新读取对象清单；`S3_BACKUP_VERIFY_INTERVAL_HOURS` 默认 168 小时，核对由下一次备份触发，不另建定时任务。届时重新计算本地全库哈希、列举远端对象并补回缺失对象。远端核对比较对象哈希名称与大小，不代表下载全部对象重新校验内容；恢复仍逐个校验 SHA-256。

适用前提：单服务端通过本应用写入文件。外部程序原地改写文件并伪造相同元数据，可能直到周期全量校验才发现；不应同时从磁盘绕过应用修改数据。

文件路径、大小、哈希均与最近成功快照一致时，普通备份不创建新快照；仍可处理到期全量核对或上次未完成的清理。恢复前保护快照可强制生成。页面显示“内容无变化，已复用最近快照”，并展示实际计算哈希和上传的数量。

新快照清单使用紧凑 JSON + gzip（S3 `Content-Encoding: gzip`），`latest.json` 改为 version 2 小指针，指向快照清单。读端兼容旧明文清单及旧完整 latest。持久清单缓存按 ETag 校验，支持条件 GET/304；变化的清单重新下载，清理前仍重新核对远端清单列表。Web 的状态和快照列表仅返回摘要，不发送数万条文件记录；列表短时缓存 60 秒，备份/清理后失效。

旧版服务无法读取新压缩格式和 latest 指针。产生新快照后，恢复必须使用支持此格式的版本；不能用旧脚本直接假设 latest 包含 files。

## 旧快照与对象清理

新快照及 latest 发布成功后，校验全部清单，再删除超出保留数量的普通快照。手动、定时备份均计入普通快照；历史 `protected:true` 和恢复前快照不自动删除。重新列举仍保留的清单，收集全部引用后，仅删除无人引用的内容对象（也包括失败上传留下的孤立对象）。最新快照和共享附件不会被清理。每批最多删除 1000 个对象，检查 S3 返回的逐项错误。

快照发布失败不清理；清单损坏停止清理；清单删除失败不继续删内容对象。清理失败不会撤销成功发布的备份，状态返回 `cleanupError` 并在 Web 显示，下次成功备份再次清理。清理中断只会残留多余对象，不会删除保留清单引用的对象。

## 恢复

1. 完整备份当前 data，确认没有待处理写入或迁移任务。
2. 在云端备份列表选择目标快照，按提示确认。
3. 下载到独立暂存区，按 SHA-256 校验；重试可复用已校验文件。
4. 校验全部完成后切换目录、重建索引。旧目录保留供回滚；异常现场不自动删除。
5. 客户端识别新的数据世代，旧的未上传编辑保留为草稿，不自动覆盖恢复后的数据。

新服务器可使用原桶及 `mynote/` 前缀恢复当前笔记和附件。恢复过程中可能暂停写入；切换中断的恢复边界见 backup-safety.md。原服务器数据库未另行备份时，单靠当前 S3 快照不能恢复笔记历史版本。

## 运行观测

每次备份/恢复的每次尝试单独存入 `data/backup-observability.sqlite`，保留最近 90 天、最多 10000 次；重启后未完成的尝试标记为 interrupted，续跑另计一次。登录后可请求 `GET /backups/observability?days=7&limit=50`（days 最大 90，limit 最大 200），获取每日统计、成功/失败/中断次数、平均及 P95 耗时、平均触发间隔和最近任务。

结构化日志事件为 `backup.started/progress/succeeded/failed/interrupted`；阶段变化或每 15 秒输出一次进度，Docker 日志轮转上限 3 × 10 MB。记录任务 ID、触发原因、尝试次数、文件数量/逻辑大小、哈希计算与复用、内容上传量、S3 各操作次数/SDK 尝试次数/重试等待、阶段耗时、快照写入锁和排队时间、CPU 与采样 RSS 峰值。网页备份任务显示耗时、实际传输量、请求数和主要耗时阶段。

`s3PutBytes/s3GetBytes` 是成功上传/完整读取的应用负载字节，包含压缩清单与指针，不含协议开销、失败的部分传输或重试重复字节，不能代替云账单。`activeUploadBytesPerSecond` 按存在上传请求的时间区间计算（并发区间去重），`averageUploadBytesPerSecond` 按整次任务计算；它们是吞吐指标，不是带宽限速。CPU/RSS 是进程级指标，包含同期其他请求；并发操作的累计耗时可能超过任务总耗时。并发上传可通过 `S3_BACKUP_CONCURRENCY` 设置，默认 8。

记录不包含正文、文件路径或密钥。观测 SQLite 和本地运行日志不包含在笔记内容 S3 快照中。
