# 可靠性模型与后续方向

当前面向一个服务端、一个备份前缀、多浏览器。每篇笔记使用 revision，每次变化使用 sequence，操作 ID 防止重试重复写入，vaultEpoch 隔离整库恢复前后的待同步修改。不同正文的并发修改生成冲突副本。

写入在单进程队列中串行化。文件通过临时文件和重命名发布，数据库保存写入意图供重启恢复；同步事件与当前索引可从 Markdown 重建。独立历史表不能从当前文件重建，须冷备数据库。

备份具备本地一致快照、增量哈希和对象缓存、异常大幅下降保护、任务持久化、SHA-256 恢复校验及受引用约束的清理。恢复保护跨重启保留，目录切换阶段的未知状态要求人工恢复。详见 backup-safety.md。

当前不保证多进程共享目录、跨主机 HA、跨文件系统切换原子性或全部硬件断电场景。S3 API 请求成功也不能证明存储提供方永远不会丢失对象；周期核对检查名称和大小，真正内容哈希在恢复时校验。

后续可选工作：附件流式上传/恢复、历史库异地备份、离线附件队列、受限代理 IP 识别、全文索引及搜索分页、大规模同步分页。每项应以实际瓶颈或需求驱动，不能视作已经交付。
