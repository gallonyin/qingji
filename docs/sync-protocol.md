# 增量同步与冲突规则

服务器是当前笔记权威源。每次变化递增全局 sequence，每篇笔记有 revision；浏览器 Dexie 事务保存缓存、游标和 outbox。Web 使用 /api 前缀代理服务端接口。

## 拉取与推送

GET /sync/pull?since=<sequence> 返回变化及对应快照或墓碑。客户端成功应用整批后推进游标。目录元数据与正文按需加载；待发送的本地正文不能被普通远端拉取覆盖。

POST /sync/push 的 changes 包含笔记 ID、operationId、baseRevision 与目标内容。相同操作 ID 返回原结果；相同正文的落后版本可幂等接受。版本冲突且正文不同则保留远端并创建稳定 ID 的冲突副本。删除和恢复同时提交本地编辑后的内容与状态，离线创建后删除的笔记首次同步直接进入回收站。

客户端收到明确结果后才删除对应 outbox 项；请求失败保留待发送内容。浏览器在可见页面定期检查（约 30 秒）及联网、编辑等事件触发同步，并非指数退避。S3 传输有独立重试机制，与浏览器同步无关。

## 数据世代

写入需携带 x-vault-epoch。整库恢复与必要重建更换世代；浏览器发现变化时，将旧 outbox 内容保留为恢复草稿，再拉取当前数据，不能把恢复前修改自动写回。首次初始化与异常游标走重新加载路径。

Web Locks 可用时协调同浏览器多标签的同步；缺失该 API 时仍依赖服务端操作幂等与版本检查，并发可能产生副本。不同浏览器互不共享本地缓存。

## 边界

离线创建/编辑/删除支持已初始化设备；离线附件上传未实现。浏览器缓存不是异地备份。退出登录不会清除全部本地缓存，第一次使用需联网。Joplin 导入链接以 UUID 定位，同名标题链接可能有歧义。
