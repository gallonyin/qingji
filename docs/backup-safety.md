# 备份和恢复保护

备份与恢复是持久后台任务。网页关闭或 HTTP 请求结束不取消任务，状态以任务接口为准。失败和中断保留记录；启动后尝试续跑尚未结束的任务。

建立本地硬链接快照期间排队写入，扫描、上传和清理期间可以保存。应用以临时文件加重命名替换笔记，快照捕获的内容不因之后编辑改变；外部直接修改原文件可能破坏这一假设，运行中不要让其他程序写数据目录。

发布前比较现存快照的 notes 和 attachments 数量及大小。任一非空类别变空或下降达到 50% 时阻止发布，返回 BACKUP_ABNORMAL_DROP。正常大规模整理也可能被阻止，应保留旧前缀，在独立前缀重新建立基线。

新快照及 latest 发布成功后，校验全部清单，清理超额普通快照及未引用对象。protected 快照与恢复前快照额外保留。损坏清单或快照删除失败阻止继续删除内容；清理错误不撤销已发布备份，任务返回 cleanupError，下次成功备份重试。需要前缀范围内列举、读取、写入及删除权限。

恢复前持久化保护文件，暂停服务器写入与备份。全部暂存文件大小和 SHA-256 校验通过后才切换目录，索引失败尝试回滚；旧目录保留在 .rollback-*。下载失败可重试，已完整文件复用。客户端通过新的 vaultEpoch 隔离恢复前的待同步内容并保留草稿。

切换阶段中断会触发 RESTORE_RECOVERY_REQUIRED。管理员必须检查正式目录、.restore-* 和 .rollback-*，恢复一致的 notes/attachments 后处理保护状态；不可仅删除保护文件强行启动。

瞬时网络错误最多尝试 5 次，每次限时 180 秒。保护文件使用原子重命名，但没有跨进程共享目录锁或完整断电 fsync 事务；只能单进程管理数据。S3 恢复不包含历史数据库，完整冷备另行停止服务复制整个数据目录。
